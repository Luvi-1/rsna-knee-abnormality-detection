## Authority and method

Authority is applied in this order:

1. Binding Kaggle Rules and the incorporated RSNA MIRA Dataset License.
2. Current competition pages, Competition Host or Kaggle Staff clarifications, and the
   authenticated official Kaggle API/CLI.
3. The legal code of a named third-party license and the Open Source Definition for what those
   names mean.
4. Contextual RSNA news and organizer pages.

The official Kaggle MCP was configured and enabled, but its competition tools were not exposed in
this task. The official Kaggle CLI 2.2.4 and the signed-in Kaggle pages were the approved fallback.
All repository evidence is public text, schemas, checksums, and aggregate counts. No identifiers,
reports, pixels, credentials, or preview content were persisted in repository or evidence files.

## Task, targets, and metric

- Predict one probability vector per whole MRI study, keyed by `StudyInstanceUID`.
- Target order is exact: `ACL`, `MCL`, `Medial Meniscus`, `Lateral Meniscus`, `Medial OA`,
  `Lateral OA`, `PF OA`, `Effusion`, `Synovitis`, `Baker's`, `Contusion`, `Fracture`.
- Submission header is the ID column followed by those 12 targets in that order.
- Main score is the unweighted macro ROC AUC:
  `(1 / 12) * sum(AUC_i for i in 0..11)`.
- Official handling of a target with only one class is unstated. Local evaluation must require both
  classes for every target and fail closed; it must not silently skip, reweight, or impute a target.
- Kaggle identity verification is incomplete and remains a blocking eligibility/prize gate.

## Data and train/test interface

The signed-in Data page reports 819,640 files and 569.76 GB: 819,635 DICOM objects and five CSV
files. The root contains `train_series/`, `test_series/`, and the five metadata files below.

| File | Exact bytes | Executable schema |
|---|---:|---|
| `sample_submission.csv` | 470 | ID plus the exact 12-target order |
| `test.csv` | 212 | `StudyInstanceUID` only |
| `test_series.csv` | 2,213 | ID, series ID, fluid-sensitive flag, fat-suppression flag, plane |
| `train.csv` | 5,690,007 | ID, report, then the exact 12-target order |
| `train_series.csv` | 3,458,834 | ID, series ID, fluid-sensitive flag, fat-suppression flag, plane |

- Current training metadata has 4,407 study rows and 24,371 series rows.
- The scoring test set is described as about 1,300 studies and replaces the example test inputs.
- Test reports are unavailable before and after notebook submission, per Competition Host.
- `PatientSex` was removed from `train.csv`; the Data page text that still lists it is stale.
- Only a small subset has official per-condition labels. Missing labels remain unknown, never
  negative, unless an approved versioned label protocol establishes otherwise.
- The DICOM layout is
  `<split>_series/<StudyInstanceUID>/<SeriesInstanceUID>/<SOPInstanceUID>.dcm`.
- The typical series contains 20–45 slices, median 30, with a long tail into the hundreds.
- Observed transfer syntaxes are Explicit VR Little Endian, Implicit VR Little Endian, JPEG
  Lossless, and JPEG 2000.
- Kaggle says DICOMs retain an allowlist of 86 metadata tags but does not publish the complete tag
  list. A host says `PatientSex` remains in the DICOM header. Code must not depend on any metadata
  tag until it is verified on the scoring-equivalent test interface.
- Class prevalence is not guaranteed to match across training, public, and private evaluation data.

## External assets, sharing, and license

- The Rules permit external data/models with adequate rights and equal access or a minimal-cost
  reasonableness path; the Overview states the stricter free-and-public rule. Until clarified, admit
  only free, public, equally accessible assets with provenance, version, license, checksum, and
  winner-delivery compatibility recorded before use.
- Private competition code or data may be shared only with recognized members of the same official
  Kaggle team. Every data user must register individually and accept the binding terms.
- Public competition code shared during the competition must use the official Kaggle forum or
  notebooks and respect all third-party rights.
- MIRA v2.0 is treated as controlling and narrow: research use only; no clinical reliance,
  redistribution, link sharing, re-identification, or unapproved commercial deployment.
- Data-derived images, reports, embeddings, derived datasets, patient-level outputs, and weights
  remain private unless the binding contract clearly permits release or written sponsor approval is
  obtained.

## Winner and efficiency obligations

Potential winners must be able to provide reproducible training and inference code, weights,
documentation, an environment specification, method details, a short video, public artifacts as
specified, and eligibility/license/tax material. The public-weight requirement is blocked for
advance release pending the MIRA clarification and memorization/extraction checks.

Efficiency eligibility requires an eligible team-selected or automatically selected submission
with private score above the sample-submission benchmark. The published score is minimized:

`AUC / (Benchmark - maxAUC) + RuntimeSeconds / 32400`
